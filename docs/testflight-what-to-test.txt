Winnow: fee refusals, peer verification receipts and recovery checks

Compact-filter checkpoint comparisons now record which peer acquisition source classes agreed, and the shared library can require two classes before a scan advances. This build keeps the previous behaviour on every network: a scan advances on whatever agreed. Source classes do not prove that peers have different operators.

Automatic peer-driven fee increases now use the majority of configured peer seats and stop at 120 sat/vB. A rate below what any connected peer would relay, or below a reported floor above that cap, is refused before signing and asks for an explicit rate; this applies to payments, fee bumps and shared-savings spends. Peer floors are relay hints, not fee estimates or guarantees that a transaction will be accepted.

After updating, check existing wallets, vaults, contact cards, balances, transaction history and payment approvals. Check fee previews and refusals, including a fee bump on a pending payment and an override typed outside the accepted range. Use test-network funds for sends and a separate test wallet for backup export and file import. Automatic cloud-backup updates should still work; replacement-device iCloud recovery remains unverified.

The shared library gains account-key signing, durable address cursors, bounded range recovery, recipient metadata, confirmation hashes and relay-only APIs. This build does not add a completed hardware-card or iPhone NFC signing flow. Recording block hashes alone does not validate an imported backup.

Report bugs at https://github.com/winnowwallet/winnow/issues. Include the app version, device, network, routing mode and steps to reproduce. Never include recovery words, private keys or wallet backup files.
